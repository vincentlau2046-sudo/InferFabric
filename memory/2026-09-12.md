## qwen38-27b 启动/推理崩溃根因分析
<!-- project: github.com/vincentlau2046-sudo/InferFabric -->

**问题**：修改 qwen38-27b-abliterated.yaml 后，启动超时 + 推理时进程崩溃。恢复原配置后正常。

**改动内容**（git 工作区未提交改动）：
- `gpu_memory_utilization`: 0.92 → 0.93
- `--max-num-batched-tokens`: 4096 → 8192
- 删除了 `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`

**根因**：
1. **启动超时**：`gpu_memory_utilization` 提高到 0.93 + `max-num-batched-tokens` 提到 8192 + 去掉 MTP，导致启动阶段（权重加载 + torch.compile AOT + CUDA graph capture + flashinfer autotune）总耗时 565.5s / 553.4s，超过 yaml 中 `startup_timeout: 540s`，IFF 判为 error。
2. **推理即退**：`0.93` 在 32GB 卡上仅剩 ~1.6GB 显存余量（预算 ~29.13GiB，权重 18.74GiB + KV 8.29GiB + graph 0.04GiB）。首个真实推理请求（100 条消息 / 308KB body）触发 Triton 内核 JIT 编译延迟尖峰 + 内存压力，vLLM 进程崩溃退出（proxy.log 10:45 起 `timed out → Connection reset by peer → Broken pipe`）。

**恢复方案**：恢复基线配置（0.92 / 4096 / 带 MTP），vLLM 18:58 重启后 48s 内就绪，19:09–19:21 持续正常服务（KV 65%，prefix cache 命中 80%）。

**教训**：
- 32GB 卡上 `gpu_memory_utilization` 从 0.92 提到 0.93 看似微小，但 32GB × 0.01 = 320MB 余量缩减，在 JIT + KV offload 叠加下足以触发 OOM 边缘崩溃
- `max-num-batched-tokens` 翻倍（4096→8192）显著增加 KV cache 分配，与 0.93 叠加放大显存压力
- 去掉 MTP 后启动路径变化，启动耗时增加

## AtomCode 调用失败根因：IFF proxy HTTP/1.0 + chunked
<!-- project: github.com/vincentlau2046-sudo/InferFabric -->
- 现象：AtomCode v5（Rust/reqwest）调 IFF :8999 报 `open failed: unexpected transfer-encoding parsed`
- 根因：IFF proxy 的 `ProxyHandler` 未设 `protocol_version`，默认 HTTP/1.0，而流式响应发 `Transfer-Encoding: chunked`（chunked 是 HTTP/1.1 特性），reqwest 无法解析该组合
- 修复：`ProxyHandler` 加 `protocol_version = "HTTP/1.1"`（沙箱改 → 验证 → 合入生产 → git push，commit `2639bc0`）
- 生效前提：手动启动的 IFF proxy 进程（原 PID 2563）需重启才生效
